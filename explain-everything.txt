1. WHAT IS THIS PROJECT?
================================================================================

SENTINEL SIEM is a full-stack Security Operations Center (SOC) dashboard.

It started as a frontend-only demo with fake JSON data and became a production-
deployed application that:

  - Ingests real threat intelligence (ThreatFox, FeodoTracker, CISA KEV)
  - Stores IOCs, security events, and logs in PostgreSQL
  - Serves a React dashboard with charts, maps, and live WebSocket updates
  - Provides incident workflow, log search, threat intel browser, and reports
  - Uses Ollama Cloud AI to explain events, IOCs, incidents, and summaries

It is suitable for academic presentation, portfolio review, and technical
interviews when you explain both strengths and demo limitations honestly.

3. TECHNOLOGY STACK
================================================================================

FRONTEND
  React 18, TypeScript, Vite 5
  Tailwind CSS, shadcn/ui (Radix primitives)
  TanStack React Query (server state)
  React Router 6
  Recharts (timeline, donut)
  Framer Motion (animations)
  Sonner (toasts)

BACKEND
  Node.js 20, Express 4
  ws (WebSocket)
  node-cron (scheduled feed sync, metrics broadcast)
  pg (PostgreSQL client)

DATA / AI
  PostgreSQL (Railway)
  ThreatFox, FeodoTracker, CISA KEV (HTTP, no keys)
  Ollama Cloud API — model gemma3:12b

DEPLOY
  Railway single service
  Build: npm run build (Vite + backend npm install)
  Start: npm start → node backend/src/index.mjs

4. ARCHITECTURE END-TO-END
================================================================================

                    ┌─────────────────────────────────────┐
                    │           USER BROWSER              │
                    │  React SPA (dist/)                  │
                    │  - TanStack Query → REST /api/*     │
                    │  - WebSocket → /ws                  │
                    └──────────────┬──────────────────────┘
                                   │ HTTPS
                    ┌──────────────▼──────────────────────┐
                    │   Node.js (backend/src/index.mjs)   │
                    │   - Express REST                    │
                    │   - WebSocketServer /ws             │
                    │   - express.static(dist)            │
                    │   - 15s event loop                  │
                    │   - cron: feeds 2h, metrics 3min    │
                    └──────────────┬──────────────────────┘
                                   │
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
        PostgreSQL          ThreatFox API         Ollama Cloud
        (iocs, events,      FeodoTracker          /v1/chat/completions
         logs)               CISA KEV JSON

REQUEST PATH — Dashboard page load:
  1. Browser GET /
  2. Server returns dist/index.html
  3. React loads, GET /api/dashboard
  4. Server queries PostgreSQL, returns JSON
  5. React renders metrics, charts, events
  6. WebSocket connects to /ws
  7. Every 15s server inserts new event, pushes { type: "event" }

5. ALL APPLICATION PAGES
================================================================================

/  DASHBOARD
   AI summary, 4 metric cards, attack map, timeline, severity donut,
   live events table, system status, attack sources list.

/incidents  INCIDENT MANAGEMENT
   API incidents from critical/high events + local drill incidents.
   Assign, advance status, timeline, AI explain.

/log-search  LOG INVESTIGATION
   Search, regex, filters, export. Query param ?q= from header.

/threat-intel  IOC INTELLIGENCE
   Indicators, campaigns, filters, Enrich Feed sync, AI explain.

/reports  EXECUTIVE REPORTS
   Live metrics + Sample compliance/SLA sections + AI narrative.

7. DATABASE TABLES AND DATA LIFECYCLE
================================================================================

iocs            — from feed sync (ThreatFox, Feodo, CISA)
security_events — from generator every 15s + seeds
logs            — from generator per event
feed_syncs      — ingestion audit

Events reference real IOC malware families and CVEs in titles/details.
Incidents API does NOT use a separate table — maps from security_events.

Full details: docs/05-DATABASE-AND-DATA-FLOWS.txt

================================================================================
